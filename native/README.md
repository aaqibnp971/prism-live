# native: the audio shim

`libprism_live_shim.dll` owns the audio device (CLAUDE.md hard rule 8). Its callback is the only place `prism_render` is ever called, and everything the engine plays goes through it on the way out. Python drives it through ctypes (`bridge/engine.py`). The C ABI is `include/prism_live_shim.h`; read that first.

The DLL in `bin/` is committed on purpose, like `vendor/lib/libprism_core.dll`: a booth laptop clones and runs without a compiler. A stale DLL cannot hide. `pls_source_hash()` returns the SHA-256 of what it was built from, `CMakeLists.txt` (the flags and the miniaudio definitions) and every file under `include/`, `src/` and `third_party/`, and a Python test recomputes that from the checkout and fails on a mismatch. The build type and the compiler are not in the hash; the SHA-256 of the DLL pinned below, which a test also checks, ties the bytes to them.

## The chain

Per block, on the audio thread, in this order (`src/process.cpp`):

| Step | What | Where |
|---|---|---|
| 0 | Take every queued control command: session gain, heartbeat level, beats, clock anchor, time origin | `take_commands` |
| 1 | `render(core, buf, n)`, i.e. `prism_render`. A non-zero result, or a NaN or infinity anywhere in what it wrote, is counted in `render_errors` and the whole block zeroed, before the high-pass can keep it. `frames_rendered += n` | `process_block` |
| 2 | High-pass the engine buffer. `engine_tap` copies it here | `src/highpass.h` |
| 3 | × engine trim × session gain, the gain ramped per sample | `LinearRamp` |
| 4 | \+ heartbeat level × heartbeat voice. Not under the session gain | `src/heartbeat.cpp` |
| 5 | True-peak limiter, the last stage | `src/limiter.cpp` |
| 6 | The same sample to every channel the device has | `render_device` |

Blocks larger than `max_block_frames` are split. MXCSR is set to flush denormals for the call and restored after it.

**High-pass.** 10th-order Chebyshev type II, five biquads in transposed direct form II with double state. At least 30 dB down at and below 62 Hz, within 1 dB from 69.35 Hz up, exactly 1.0 at Nyquist. The coefficients are generated by `tools/design_highpass.py` into `src/highpass_coefficients.h`; `python tools/design_highpass.py --check` fails if the header differs from the design. Order 10 at 30 dB cannot be within 1 dB at 69.3 Hz (that needs order 10.03), so the 1 dB edge is 69.35 Hz; 69.3 Hz is 1.03 dB down and the sub stem's D2 at 73.4 Hz is 0.11 dB down. The prototype is designed for 30.001 dB so that "at least 30 dB" holds without a rounding tolerance.

| Hz | 20 | 36 | 44 | 50 | 55 | 62 | 65 | 69.3 | 69.35 | 73.4 | 100 | 1000 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| dB | −30.09 | −30.03 | −58.78 | −30.01 | −51.38 | −30.00 | −9.59 | −1.03 | −1.00 | −0.11 | 0.00 | 0.00 |

**Session gain and trim.** Linear. A new target ramps in a straight line over `ramp_ms` (rounded to whole frames) from wherever the gain is when the audio thread takes the command, and lands on the target exactly. The trim is static, set at open, default −6 dB.

**Heartbeat layer.** Minimal in prompt 2.5; prompt 2.6 replaces the internals behind the same ABI. A beat's `t_play` becomes an output frame through the anchor, `F = anchor_frame + round((t_play − anchor_ms) × 48)`, and its voice starts at input frame `F − latency`, so its onset leaves the limiter on frame `F`. A beat whose onset is before the current block is dropped and counted, never played late. Voice: 44 Hz from phase 0, 8 ms raised-cosine attack, half-cosine decay over min(220 ms, 0.55 × rr), envelope peak 1.0. Output frame k is the k-th sample written out, so with the device running, the first callback after `pls_set_time_origin_ns` anchors the first output frame of its buffer (the block start, less the block's offset when a buffer is split into blocks) to QueryPerformanceCounter, converted to nanoseconds as CPython 3.11's `perf_counter_ns` does, plus one device period: when the device plays that frame. Offline, the anchor is the first frame of the `pls_render_offline` call, with no period.

**Limiter.** −1.0 dBTP ceiling, internal target −1.5 dBTP. A delay and a gain, nothing else: well below the ceiling the output is the input, `pls_latency_frames()` later. The detector interpolates in two stages, a half-band windowed sinc to 96 kHz (1024 taps each side) and then 4x of that (12 taps each side), with parabolic refinement of each 8x point. Its required gain goes through a hold of L + 1 + 2G samples, an 80 ms release and an L + 1 sample moving average, with L = 96 and G = 512, and the output is delayed so that every sample within G of a detected peak gets a gain no larger than that peak needs. The alignment proof, and what is not guaranteed, are in `src/limiter.h`.

`pls_latency_frames()` is **1639 frames, 34.1 ms**: L + G + the detector's 1031. It moves every output frame, the heartbeat's included, by the same amount. It is taken off once, where a beat is placed (its voice starts at input frame `F − latency`), and never added to the anchor, which is already an output frame: added there too, every beat on the device would sound 34.1 ms after its `t_play`. `shim_dsp_test` fails if it is.

## Limiter margin

`tests/shim_dsp_test.cpp` renders adversarial input through the whole chain (trim 0 dB, session gain 1, heartbeat at 0 dBFS every 400 ms) and measures the output with a reference true-peak meter that shares no code with the limiter: double precision, a half-band stage of 4096 taps each side, then 16x of 48 kHz. On 14 September:

| Input | Output true peak |
|---|---|
| +6 dBFS uniform white noise, 10 s | −1.369 dBTP |
| Gaussian noise, σ at +6 dBFS, 5 s | −1.382 |
| +12 dBFS noise bursts of 50 ms after silence | −1.421 |
| Noise with its level jumping ±18 dB every 97 frames | −1.442 |
| Full-scale square waves at 997 Hz, 1 kHz and 100 Hz | −1.499 |
| +6 dBFS sine at fs/4, phased for the largest inter-sample peak | −1.500 |
| +12 dBFS impulses and doublets | −1.496 |
| 1 kHz bursts at +10 dBFS starting on a crest | −1.499 |
| +6 dBFS chirp, 20 Hz to 20 kHz | −1.498 |
| Two tones at 21 and 23 kHz | −1.496 |
| sign(sinc) sequences of 33 samples | −1.498 |
| *Gated alternating ±1, energy at exactly fs/2 (not guaranteed)* | *+0.820* |

The worst guaranteed case is 0.37 dB under the ceiling. At its worst interval, a 16,384-tap sinc evaluated at 512 points per sample reads 0.02 dB higher than the reference meter. Why −1.5 and not −1.2: full-band noise carries sinc tails longer than any detector, and the measured overshoot of the target is 0.13 dB, which would leave −1.2 only 0.07 dB. A 64-tap-per-phase detector, the first design, put +6 dBFS white noise out at +0.29 dBTP with a −1.2 dBTP target. The last row is a signal whose reconstruction grows with the logarithm of its length; no finite lookahead bounds it, and nothing in this chain produces it (the engine's low-pass tops out at 12 kHz, the heartbeat is 44 Hz). A naive square wave whose period is 2 mod 4 samples belongs to the same class, because it has a component at exactly fs/2, and a render that starts or stops it gates that component. Measured the same way, full scale, 3 s from silence: period 6 (8 kHz) −0.67 dBTP, period 10 (4.8 kHz) −0.99, period 14 (3.4 kHz) −1.12, period 50 (960 Hz) −1.41, against period 48 (1 kHz) −1.50. A test of the ceiling should use a square whose period is not 2 mod 4, as `shim_dsp_test` does, or a reference meter no longer than the detector (1024 taps each side).

`tests/test_shim.py` measures the same kinds of material from Python with `tests/audio_meters.py`, whose first stage is an FFT reconstruction, the unwindowed sinc, with 16,384 samples of context either side (readings move by under 0.001 dB from 4,096 to 131,072). That meter reads full-band noise higher than the windowed one above, so the white-noise margin is smaller than the table says: on 14 September +6 dBFS uniform white noise came out at −1.29 dBTP (worst of 24 seeds and levels −1.28, worst 10 s window of a 240 s render −1.27), Gaussian noise −1.38, noise bursts −1.37, and everything with a spectrum that thins out before fs/2 at −1.50. The worst case is 0.27 dB under the ceiling, not 0.37.

The chain costs about 2 to 4 % of one core in real time on the development laptop (60 s of audio in 10 ms blocks: median 0.16 to 0.35 ms per block).

## Threading

Exactly one control thread makes every `pls_*` call except `pls_render_offline`. The control calls validate their arguments, then push a POD command into a wait-free single-producer single-consumer queue (`src/spsc.h`), sized at open. A full queue returns `PLS_ERROR_QUEUE_FULL` and queues nothing. The audio thread (the device callback after `pls_start`, or the caller of `pls_render_offline` while stopped, never both) drains the queue at the start of every block. Counters are lock-free atomics, written only by the audio thread and read from any; the one exception, `device_unrequested_stops`, is counted by whichever thread first sees a lost stream, once per stream by compare-and-swap.

Nothing on the audio thread allocates, locks, logs or does I/O (hard rule 4). Everything it touches is allocated in `pls_open`. `tests/rt_tripwire_test.cpp` replaces `operator new`/`delete` (plain, nothrow and aligned) and wraps `malloc`, `calloc`, `realloc`, `free` and `_aligned_*` at link time, then renders 82 s through both the offline and the device-callback paths while a second thread hammers the control calls, with the limiter engaged. Zero allocations and zero frees while armed. Its first line of output is `source <pls_source_hash()>`, so `tests/test_shim.py` can refuse an executable built from other sources.

**Device.** miniaudio 0.11.25 (`third_party/miniaudio`, public domain or MIT-0, copied from the engine's clone), WASAPI only. Playback, float32, the device's own channel count, 48 kHz, a 10 ms period, no pre-silenced buffer, no clipping. `wasapi.noAutoConvertSRC` is set: without it, WASAPI shared mode resamples 48 kHz to the endpoint's mix rate itself and miniaudio reports 48 kHz anyway. With it, the internal rate is the endpoint's, and `pls_start` refuses anything but 48 kHz with `PLS_ERROR_SAMPLE_RATE`.

The stream never follows a default-device change (`wasapi.noAutoStreamRouting`). Left on, miniaudio would reopen the stream on the new default endpoint by itself, through its resampler if that endpoint is not at 48 kHz, with the device period and the time anchor stale. So the stream stays on the endpoint it opened: plug the headphones in before `pls_start`, and plugging in a USB or HDMI device at the booth does not take the sound away from them. If the endpoint goes away, the stream stops by itself, `frames_rendered` stops advancing, and `device_unrequested_stops` in `pls_stats` counts it. miniaudio's notification callback counts that stop; because miniaudio posts no notification when its own stop of a lost endpoint fails, `pls_get_stats`, `pls_start` and `pls_stop` also read the device's state, and each lost stream is counted once. Recovery is `pls_stop` (which releases the lost device), `pls_set_time_origin_ns`, `pls_start`: the device is opened afresh, so the 48 kHz refusal runs again and the period is read again. A kept device that fails to start is reopened the same way, once. No test opens the real device, so none of this is exercised by a test.

## Build

MSYS2 UCRT64 (`D:\ANP\tools\msys64\ucrt64\bin` on `PATH`), no Visual Studio:

- GCC 16.1.0 (Rev5, Built by MSYS2 project)
- CMake 4.4.0
- Ninja 1.13.2
- GNU Binutils 2.46.1

From the prism-live root:

```
cmake -S native -B native/build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++
cmake --build native/build
ctest --test-dir native/build --output-on-failure
cp native/build/libprism_live_shim.dll native/bin/
sha256sum native/bin/libprism_live_shim.dll
```

- RelWithDebInfo: `-O2 -g -DNDEBUG`, C++17.
- First-party sources: `-Wall -Wextra -Wpedantic -Werror`. miniaudio compiles without warnings flags.
- Hidden visibility. Only the `PLS_API` functions are exported (`PLS_BUILD_SHARED`).
- The DLL links with `-static -s -Wl,--no-insert-timestamp`: libstdc++, libgcc and winpthread are linked in, symbols and debug info are dropped, and the PE timestamp is 0.
- `src/` is on the include path through `-iquote`, never `-I`: `src/process.h` would otherwise replace the C runtime's `<process.h>` for every file that includes `<pthread.h>`.
- The source hash is computed at configure time: SHA-256 over `CMakeLists.txt` and every file under `include/`, `src/` and `third_party/`, sorted by path relative to `native/` with forward slashes, each contributing `path + "\n" + contents with CRLF as LF + "\n"`. No build type or compiler is folded in. Every hashed file is a configure dependency, so an edit re-runs it.

The ctest suite: `rt_tripwire_test` (the allocation tripwire) and `shim_dsp_test` (83 checks: ABI version, the `pls_stats` layout and argument checks, the queue under two threads, exact frame counts, the high-pass response at 12 frequencies, exact gain ramps, beat onsets on their anchored frames, late and full beats, the time origin's anchor offline and on the device callback's path with a split buffer, the detector against exact sine peaks, the limiter margin above, transparency, and NaN and infinity from the render function). About 10 to 30 s together on the development laptop.

| `pls_abi_version()` | 2 (`pls_stats` gained `device_unrequested_stops`, appended) |
| Exports | The 16 `PLS_API` functions of `include/prism_live_shim.h`, and nothing else |
| Imports | `KERNEL32.dll` and the Windows Universal C Runtime (`api-ms-win-crt-*`) only. miniaudio loads `ole32.dll` and the audio endpoints at run time |

With the same toolchain the build is byte for byte reproducible: a second build directory on another drive, and a copy of the sources with CRLF line endings in another directory, both gave this SHA-256 and this source hash (14 September, rebuilt for ABI 2).

To change the shim: edit, build, run ctest, copy the DLL to `bin/`, and update the size, SHA-256 and source hash above. Commit the sources and the DLL together. A DLL built with a different compiler or binutils has a different SHA-256 and is a different library until it is checked again. To debug a crash inside the shim, build without `-s` and load that DLL instead; never commit it.
